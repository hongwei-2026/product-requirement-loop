# 任务 Issue 正文标准块（复制进每个 task Issue）

> 维护者建 Issue 时把下面两节贴到任务专属内容之后；勿只写在评论里。

---

## 如何接取 / 放弃 / 同步仪表盘

**标准顺序（必须）：**

1. 同学评论 `/claim`（仅登记意向，**接取人栏仍为空**）  
2. 同学开 Design PR（`docs/designs/#N-….md`）并邮件通知  
3. 维护者 **Merge** Design PR  
4. 维护者在同学 `/claim` 语境下评论 `/accept @同学ID` → **接取人栏才写入该 ID**  
5. 同学再开 Implementation PR  

命令写在**本 Issue 评论区**，单独一行。

| 你要做的事 | 评论命令 | 接取人栏 |
|------------|----------|----------|
| 登记意向 | `/claim` | 仍为 — |
| 维护者批准（Design 已合并后） | （仅 @hongwei-2026）`/accept @你的ID` | **写入 @你的ID** |
| **自己放弃** | `/cancel` 或 `/release` | 清空为 — |
| 维护者清掉别人的认领 | `/reject-claim` | 清空为 — |
| 合并后计分 | `/score N` | 标已完成 |

**硬性规则：**

- 同一 GitHub 账号同时只能有 1 个进行中任务（意向或已锁定）。想换题必须先 `/cancel`。  
- **进度新鲜度：** 认领后关联的 Design/Impl PR 必须 **至少每 30 天有一次更新**；超过 30 天无更新，系统 **自动释放** 任务（清接取人，重新开放）。

| 你要做的事 | 评论命令 | 仪表盘会怎样 |
|------------|----------|--------------|
| 接任务 | `/claim` | 「进行中的认领」出现你与本 Issue |
| 维护者正式锁定 | （仅 @hongwei-2026）`/accept @你的ID` | 状态 → 已锁定实现中 |
| **自己放弃** | `/cancel` 或 `/release` | 认领记录**自动删除**，任务重新开放 |
| 维护者清掉别人的认领 | `/reject-claim` | 同上 |
| 合并后计分 | （维护者/必审人）`/score N` | 排行榜刷新 |

- 仪表盘：[任务仪表盘.md](./任务仪表盘.md) · [HTML](../dashboard/index.html)
- 接取后仍须：Design PR → 邮件 `feizi_050920@qq.com`（Issue + Design PR + GitHub ID）→ 等 `/accept`

## 交付物规范（Implementation PR 缺一不可）

1. **代码**：PR 标题 `[Impl] #<本Issue> …`，正文含 `Fixes #<本Issue>`；作者须为已 `/accept` 的 Assignee  
2. **演示视频链接（必填）**：可公网打开的链接（B 站 / 飞书云文档·妙记 / 录屏分享等），展示完整操作路径；写在 PR 正文「演示视频」一节  
3. **截图（必填）**：至少 2 张（改前/改后，或关键成功界面），**直接贴在 PR 正文**，不要只写本地路径  
4. 禁止截图或视频中出现 API Key / `.env` 内容  

缺视频或截图时，必审人可要求补齐后再 Approve。

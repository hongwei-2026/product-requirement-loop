## 二、评论命令（必须原样写在 Issue 评论区）

| 命令 | 谁可以发 | 作用 |
|------|----------|------|
| `/claim` | 任意登录用户 | 登记接取意向；**不会**写入接取人栏；一账号一进行中 |
| `/accept @username` | **仅 hongwei-2026** | 须该用户已 `/claim`，且其 **Design PR 已合并**；成功后 **接取人栏写入 ID** 并锁定 |
| `/cancel` 或 `/release` | 当前认领人 / 受指派人 / 维护者 | 放弃；接取人栏清空 |
| `/reject-claim` | 仅 hongwei-2026 | 强制清空别人的认领 |
| `/score N` | hongwei-2026 或必审人 | 记分并刷新排行榜 |

> 命令单独成行。  
> **接取人栏写入时机：** 仅 `/accept` 成功之后（不是 `/claim` 当时）。

### 接了任务后，仪表盘怎么同步？

| 动作 | 仪表盘变化（Actions 自动 commit） |
|------|-----------------------------------|
| 有人 `/claim` | 「进行中的认领」可看到意向；**接取人栏仍为 —** |
| Design PR 已合并且你 `/accept @他` | **接取人栏写入 @他**；状态已锁定 |
| 他 `/cancel` 或 `/release` | 接取人清空为 — |
| `/score N` | 排行榜加分；接取人标成已完成 |

## 三、设计 PR 要求（Design）——提交位已建好

**提交位（落库文件，不只写在评论里）：** [`docs/designs/`](../designs/README.md)

1. 从 `main` 开分支：`design/#<issue>-简短英文`  
2. 复制 `docs/designs/_TEMPLATE.md` → `docs/designs/#<issue>-简短英文.md` 并填完  
3. 开 PR 时 **选择模板 Design**；标题：`[Design] #<issue> 简要标题`  
4. PR 正文写 `Related to #<issue>`（**不要** `Fixes`，以免未实现就关 Issue）  
5. **不要在 Design PR 里塞完整实现**（可放伪代码/接口草图）  
6. 发邮件主题：`[Design] #<issue> <你的GitHubID>`，附 Issue + Design PR + GitHub ID  
7. 流水：`Enterprise PR / design-gate` 会检查设计文档是否落在本 PR 的 `docs/designs/`

## 四、实现 PR 要求（Implementation）

1. 分支：`feat/#<issue>-简短英文`  
2. 开 PR 时 **选择模板 Implementation**；标题：`[Impl] #<issue> 简要标题`  
3. 正文必须有：`Fixes #<issue>`（或 `Closes #<issue>`）  
4. 作者必须是 Issue **Assignee**（已被 `/accept` 锁定），否则 `task-lock` 失败。  
5. 通过 CI：`verify_docs_layout` / `verify_lessons` / `verify_security` 等。  
6. **交付物三件套（缺一不可，写在 PR 正文）**：
   - **代码**（本 PR）
   - **演示视频链接**（可公网打开）
   - **截图 ≥2 张**（直接贴图）
7. 流水：`Enterprise PR / delivery-artifacts` 自动检测视频与截图；缺则红灯。  
8. 补材料后在 PR 评论发送：`/recheck`（重跑企业级套件）。  
9. 视频/截图禁止出现 API Key；缺材料时必审人可拒 Approve。

> 接取/放弃说明写在 **Issue 描述正文**（见 [任务Issue标准块.md](./任务Issue标准块.md)）。  
> **审核员**请看：[审核员指南.md](./审核员指南.md)（本文是给同学的）。

## 五、难度与默认积分

| 难度 | 标签 | 默认积分 | 说明 |
|------|------|----------|------|
| 简单 | `difficulty:easy` | 10～15 | 文案/展示/小交互，触及面小 |
| 中等 | `difficulty:medium` | 25～35 | 单模块功能，需设计与自测 |
| 难 | `difficulty:hard` | 50～60 | 架构/异步/压测流水，回归面大 |
| 特难 | `difficulty:extreme` | 70～90 | 量潮扩展能力（下游资产/多人协作/可复现/数据源收敛） |

具体分数以 Issue 正文「积分」字段为准；`/score` 可按完成质量微调。

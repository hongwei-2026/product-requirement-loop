# 产品需求梳理智能体 · 操作手册（交付版）

> 面向**交付使用**，不是课题阶段说明。  
> 产品入口：**http://127.0.0.1:8765/**  
> 仓库内也可在页面右上角点 **「使用指南」** 查看同内容摘要。

**版本要点（相对 demo）：** 官方全量日志库、阶段机落盘（Step2 通过后可定稿）、打叉需显式确认、定稿人必填、错误时遮罩会关闭、交付冒烟脚本可自检。

## 0. 30 秒上手

1. 双击 `start-with-ai.bat`（黑窗勿关）  
2. 打开 http://127.0.0.1:8765/  
3. **日志库** → 选一条「聚焦摘录」→ 选用并去工作台  
4. 运行 Step1 → ✓ 通过 → 运行 Step2 → ✓ 通过 → 填姓名定稿 → check  

正式交付时：第 3 步改选**对应产品流 + 日期的全文**，不要用摘录。

## 1. 这是什么

把**产品研发日志**变成**可定稿的用户故事**：

| 步 | 谁做 | 产出 |
|----|------|------|
| Step1 | AI 整理 → **人确认** | 需求故事（一件事） |
| Step2 | AI 抽取 → **人确认** | 用户故事 JSON |
| Step3 | **人定稿** → 机器 check | `accepted.json` |

原则：

- **人两次把关**，AI 不得编造原文没有的能力  
- 通过后**锁定**；打叉只重跑当前步  
- 全程可追溯（`journal_id`、`revisions`）

## 2. 安装与启动（第一次）

### 2.1 环境

1. 安装 Python 3.10+  
2. 双击 **`setup阶段1环境.bat`**（创建 `project/.venv` 并装依赖）  
3. 复制 `project/.env.example` → `project/.env`，填写 `AGNES_API_KEY`  
   - **不要**把 `.env` 提交到 GitHub

### 2.2 同步官方日志库（交付必做）

```bat
cd 仓库根目录
project\.venv\Scripts\python.exe scripts\sync_journals.py
```

成功后：侧边栏「日志库」应显示 **数十条日志、多个产品流**（冒烟期望 catalog ≥ 20，交付建议 ≥ 50）。

### 2.3 日常启动

双击 **`start-with-ai.bat`**

| 正常 | 异常 |
|------|------|
| 弹出黑窗且保持运行 | 黑窗秒退 → 看是否缺 `.env` / 缺 venv |
| 浏览器打开登录页 | 打不开 → 等 5 秒再开 `http://127.0.0.1:8765/login.html` |
| 用账号登录后进工作台 | 演示账号：`demo` / `demo1234` |

数据存在本地库：`project/data/product_requirement.db`（用户、审核历史、定稿档案、待人审）。

## 3. 界面怎么读

| 区域 | 作用 | 注意 |
|------|------|------|
| **工作台** | 跑 Step1→2→3 | 交付主战场 |
| **日志库** | 浏览 / 筛选 / 选用全部日志 | 可勾选批量 AI |
| **待人审** | AI 批量跑完后的排队 | 人逐条审，不能批量一键过 |
| **定稿档案** | Step3 定稿后的检索台账 | 已审过默认不必重审；与「日志库」原文不是一回事 |
| 流水线 1/2/3 | **当前进度提示** | 只读，不是另一套日志列表 |
| 左栏 / 右栏 | 原文 vs AI 产物 | **各自独立滚动** |
| 底部按钮 | 运行 / 通过 / 打叉 / 定稿 / check | **通过与打叉都要写理由** |
| **审核历史** | 可读时间线 | 谁 / 何时 / 哪条日志 / 结论 / 理由 |
| 右上角 **使用指南** | 产品内摘要 | 与本手册同步维护 |

顶部「当前阶段」含义：

| 阶段显示 | 你该做什么 |
|----------|------------|
| 待开始 | 选日志，运行 Step1 |
| Step1 待确认 | 对照原文，通过或打叉 |
| Step1 已锁定 | 可运行 Step2；或解锁 Step1 重做 |
| Step2 待确认 | 检查「用户要…」与出处 |
| Step2 已通过 | 填定稿人 → 生成 accepted.json |
| 已定稿 | 可再跑 check；或清空重来 |

## 4. 怎么选日志（交付关键）

### 4.1 决策表

| 今天的目标 | 选什么 | 为什么 |
|------------|--------|--------|
| 验证产品能不能跑通 / 拍操作视频 | **聚焦摘录**（用途=试跑） | 字少、快、费用低 |
| 正式梳理并定稿 | **产品流 + 日期** 的**全文** | 与官方日志一致、可审计 |
| 刚开完会 / 飞书纪要 | **粘贴** 或 **上传 .md** | 立刻进自定义库并选用 |

### 4.2 推荐选法

1. 先想清楚：**今天只梳理一件事**  
2. 进 **日志库** → 筛产品流 → 筛用途（试跑 / 正式）→ 搜日期或标题  
3. 点 **选用并去工作台**

换日志会**清空本轮产物**（会弹确认）。不要在正式半成品中途随意换日志。

### 4.3 不要踩的坑

- 正式定稿却选了摘录 → 故事不完整，check / 评审会质疑  
- 把左侧「流水线步骤」当成日志列表 → 日志只在 **日志库**  
- 库里只有几条 → 未跑 `sync_journals.py`

## 5. 标准操作流程（SOP）

1. 填写顶栏旁的 **审核人**  
2. Step1：运行 → 对照 → **通过也要写理由**（或打叉写原因）→ 确认提交  
3. Step2：同上  
4. Step3：定稿人姓名 → **生成定稿并归档** → check  
5. 在 **定稿档案** 可检索；日志库可筛「已定稿」

**批量：** 日志库勾选 →「批量 AI → 待人审」→ 待人审页「开始人审」。

重新梳理：清空本轮产物，或换日志。

## 6. 产物与路径

相对 `project/trials/case-01/`：

| 文件 | 含义 |
|------|------|
| `output/requirement-story.md` | Step1 当前故事 |
| `output/stories.json` | Step2 条目 |
| `output/locked/step1-requirement-story.md` | Step1 锁定副本 |
| `output/locked/step2-approved.json` | Step2 已通过（可定稿） |
| `output/accepted.json` | 定稿（含 revisions、journal_id） |
| `output/session.json` | 会话元数据 |

评审时打开 `accepted.json` 即可核对：谁定的、基于哪条日志、改过几轮。

## 7. 故障排除

| 现象 | 处理 |
|------|------|
| 页面打不开 | 黑窗是否在；重跑 `start-with-ai.bat` |
| 提示缺少 AGNES_API_KEY | 检查 `project/.env`；勿提交密钥 |
| 转圈不停 / 按钮无反应 | Ctrl+F5；看黑窗是否报错退出；再试一次 |
| 提示系统正忙 | 等当前请求结束；勿连点多次运行 |
| 日志库只有几条 | `scripts\sync_journals.py` |
| 8765 端口占用 | `scripts\free_port_8765.bat` 后再启动 |
| Step2 已通过但看不到定稿区 | Ctrl+F5；确认存在 `locked/step2-approved.json`；仍不行则清空重来 |
| 定稿失败「姓名」 | 在定稿人框填真实姓名 |
| check 未通过 | 看提示；常见编造/句式 → 打叉重跑对应步 |

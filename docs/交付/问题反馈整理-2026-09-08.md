## 问题 3：Web 跑 Step1 报「连不上服务」，进程像挂掉

### 现象复现

- Web 点「运行 Step1」后长时间加载遮罩。  
- 约 3 分钟后报错：`连不上服务：请确认已启动 start-with-ai.bat`。  
- 后台日志：本地 Web 服务进程被中止，端口释放。

### 根因（审阅方定位）

1. **模型与任务不匹配（主因）**  
   - 使用 `deepseek-v4-pro`，默认带深度思考（Reasoning）。  
   - 数千字研发日志时，单次生成可达 **280s+（近 5 分钟）**。  

2. **同步阻塞 + 超时截断**  
   - `POST /api/loop/step1` 同步阻塞。  
   - OpenAI 客户端硬编码 `timeout=180s`（3 分钟）。  
   - 客户端超时抛错，前端连接被掐，页面误报「连不上服务」。

### 改造建议

**临时（立即恢复可用）**

- [ ] `project/.env` 中 `DEEPSEEK_MODEL` 改为 **`deepseek-v4-flash`**（需求提炼 / JSON 抽取实测约 3～5s）。  
- [ ] 若坚持 Pro：  
  - 将 `llm_config.py` 客户端超时调至约 **600s**；  
  - 请求显式关闭思考链，例如：`extra_body={"thinking": {"type": "disabled"}}`。

**长期（体验）**

- [ ] Step1/Step2 **异步轮询或 SSE**，避免单条同步 HTTP 硬顶。  
- [ ] 前端：超时重试；报错区分 **「服务已停止」** vs **「AI 推理超时」**。  
- [ ] 压力测试：覆盖「很长日志 + 推理类模型」场景，避免再被偶然测出。

### 相关文件（预期）

- `project/.env` / `project/.env.example`  
- `project/llm_config.py`  
- `project/web/loop_session.py`（或 Step1 API 路由）  
- `project/trials/case-01/app.html`（前端提示文案）

## 问题 4：`Connection error.` 真因是 SOCKS / 缺 socksio（macOS 常见）

### 结论先行

界面/日志常见 `Connection error.`，底层真实异常是：

```text
ImportError: Using SOCKS proxy, but the 'socksio' package is not installed.
Make sure to install httpx using `pip install httpx[socks]`.
```

被 OpenAI SDK 包装成：

```text
openai.APIConnectionError: Connection error.
```

### 根因

- 系统或终端配置了 **SOCKS 代理**。  
- `openai` → `httpx` 默认 `trust_env=True`，会读系统代理。  
- 发现 SOCKS 但未装 `socksio`，传输层初始化直接崩。

### 生产规约（审阅方）

- **反模式**：裸 `OpenAI(api_key=..., base_url=...)`，任由宿主机代理污染。  
- **规范**：显式注入 `httpx.Client(trust_env=False, ...)`，阻断环境代理隐式影响。

### 建议改法（`project/llm_config.py`）

```python
import httpx
from openai import OpenAI

def make_client() -> OpenAI:
    # ...
    http_client = httpx.Client(trust_env=False, timeout=180.0)
    return OpenAI(api_key=key, base_url=base, http_client=http_client)
```

- [ ] 写入 `make_client()`（或等价工厂）。  
- [ ] 友好错误文案：若仍遇代理类 ImportError，提示「代理/ socksio」而非笼统「连不上服务」。  
- [ ] 文档注明：本机开代理时，产品默认直连 API（`trust_env=False`）。

## 问题 5：网络与模型响应需重新适配；多测模型

### 现象 / 诉求

- 实测 debug 次数偏多，稳定性相对上一版体感退步。  
- 即便切到 **V4 flash** 仍有问题。  
- 建议围绕 **网络 + 模型响应** 重新适配。  
- **多测几个模型**，尤其 **高性能 / Pro** 的兼容效果（超时、思考链、报错语义）。

### 建议动作

- [ ] 模型矩阵冒烟：flash / pro（关思考）/ pro（开思考）× 短日志 / 长日志。  
- [ ] 统一超时、重试、取消策略；前端状态与后端一致。  
- [ ] 失败信息分级：网络代理、鉴权、超时、JSON 解析、服务进程退出。  
- [ ] 把长日志 + 慢模型场景纳入 `verify_lessons` 或单独压力脚本（能自动化的部分）。  
- [ ] 回归：换模型后 Step1/Step2/定稿门禁仍绿。

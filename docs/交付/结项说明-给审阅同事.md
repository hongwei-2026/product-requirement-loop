## 1. 验收实测数据在哪？（不是漏了）

立项 6 条硬门槛的**实测对照表**在这里：

**[`project/trials/case-01/trial-report.md`](../../project/trials/case-01/trial-report.md)**

| 门槛 | 标准 | 实测（见 trial-report） |
|------|------|-------------------------|
| 编造条数 | = 0 | 0 |
| source_quote 通过率 | = 100% | 100% |
| 句覆盖率 | = 100%（含例外说明） | 未句句成故事的写入 `uncovered.md`，并在定稿 `review.comments` 人工确认 |
| 反馈点 | ≥ 1 次 | 实测 ≥ 1（含打回重跑） |
| accepted.json | 每条 `approved: true` 且 `revisions` 非空 | 有 |
| check.py | 退出码 0 | 0 |

**一键复验（Windows 最省事）：** 双击仓库根目录 **`验收门槛.bat`**

或在**本仓库根目录**（含 `start-with-ai.bat` 的那一层）打开终端：

```bat
cd /d D:\量潮科技\课题申请-product-requirement-loop
project\.venv\Scripts\python.exe scripts\verify_acceptance.py
```

> 若当前目录是 `D:\量潮科技`（上一级），命令会失败。必须先进入 `课题申请-product-requirement-loop`。

定稿黄金样本（冒烟 reset 不会丢）：`project/trials/case-01/golden/accepted.json`  
工作台当前定稿：`project/trials/case-01/output/accepted.json`（自检脚本优先读这里，没有则读 golden）

或手动 check：

```bash
# Windows
project\.venv\Scripts\python.exe project\check.py project\trials\case-01\output\accepted.json --source project\trials\case-01\input\active-journal.md --strict

# Mac / Linux
project/.venv/bin/python project/check.py project/trials/case-01/output/accepted.json --source project/trials/case-01/input/active-journal.md --strict
```

**重要：** `--source` 必须和定稿时用的原文一致（看 `accepted.json` → `meta.source_file` / `journal_id`）。拿错文件会误报「全是编造」。

前台点一遍只能确认「流程能走、能打回、能定稿」；**编造=0 / 通过率 / 覆盖率 / revisions** 请用上面的 `check.py` + `trial-report` 核对。

## 2. 为什么立项写「不做 UI」，交付却是 Web？

| | 说明 |
|--|------|
| **立项时** | 先保证 Agent 侧 Loop 能跑通：CLI + yaml + 反馈点。边界写死：不做产品云画布、不接飞书、不做 JSON→SQL，也写了「不做 UI」以免范围失控。 |
| **交付时加了 Web** | 实训/结项标准强调「能不能让同事用起来」。CLI 对非技术同事不友好，所以加了本机 Web（登录、日志库、工作台、定稿档案、审核历史）。 |
| **没变的边界** | 仍不接飞书 API、不做 JSON→SQL；Web 只跑在本机 `127.0.0.1:8765`。 |
| **怎么理解** | Web 是**加餐**，不是推翻立项；核心仍是「日志 → Step1 → 人 → Step2 → 人定稿 → 可溯源」。 |

无界面时仍可用 CLI：`run-stage4-loop.bat` 或 `python project/implementation.py trials/case-01`。

## 3. `loop_runner.py` 更大，还复用官方 LangGraph 吗？

**还在用。** 关系是：

```
官方 devops-code/implementation.py（LangGraph）
        ↓ 本地化
project/implementation.py     ← 官方执行器入口仍在（可读 yaml、interrupt、dry-run）
        ↓ 默认调用
project/loop_runner.py        ← 本课题阶段 4：逐步反馈 / 锁定 / 打叉只重跑当前步 / 写 accepted.json
        ↓ Web 也调用同一套
工作台 API
```

- `implementation.py`：**复用官方 LangGraph 执行器**（来源见文件头注释与 `project/IMPLEMENTATION.md`）。  
- `loop_runner.py` 更大：因为把「人停两次、锁定、定稿、demo 反馈序列」写清楚了，文件自然更长。  
- 默认跑 `implementation.py` 会走到 `loop_runner` 闭环；需要旧版连跑可用 `--langgraph`（若保留该开关）。

**一句话：** 不是另起炉灶换掉官方执行器，而是官方入口 + 本课题闭环编排。

## 4. Mac / Linux 怎么启动？（针对首次部署反馈）

Windows 可继续双击 `.bat`。Mac / Linux 用脚本：

```bash
# 第一次
chmod +x setup.sh start-with-ai.sh
./setup.sh
cp project/.env.example project/.env   # 填写 AGNES_API_KEY

# 同步日志（推荐）
project/.venv/bin/python scripts/sync_journals.py

# 日常启动（勿关终端）
./start-with-ai.sh
```

浏览器打开：http://127.0.0.1:8765/  
演示账号：`demo` / `demo1234`

更细的操作见 [`产品操作手册.md`](./产品操作手册.md)。

# 需求故事

## 全局故事（一件事）
本文档旨在定义一套“人机协同的新语法”与标准化产品研发体系，将传统的用户故事地图与事件风暴升级为AI辅助的结构化梳理工具。通过固定HTML格式与命令行入口，实现从需求摘取、方案实施、验收运营的全流程可复用、可脱离平台独立运行。系统接受AI与人工互校的容错路径，最终依靠标准化规范与集体决策机制，打造一套能持续提升团队研发效率的云原生协作框架。

## 背景
传统用户故事地图和事件风暴工作坊组织成本高、从碎片语音到结构化需求的转化效率低。现有AI已能承接信息量大、枯燥的整理与对比工作，但完全自动生成（尤其是任务级与故事级）仍不成熟，需人机协同反复试验。研发团队已验证固定HTML格式、事件流优先展示及命令行操作的可行性，并观察到AI能力跃迁下验证/Review成本先升后降、执行成本持续降低的规律，具备沉淀标准化体系的条件。

## 要做什么
1. **升级需求梳理**：AI从原始碎片话语中捕捉用户故事，按层级划分用户活动/任务/故事细节，定位到图上合适位置，人工复核调整，替代旧版用户故事地图。
2. **构建事件风暴新形态**：优先保障事件流顺序的科学展示；允许Command与多事件结果非严格一一对应，粗糙版先跑通，再抽象准确原型。
3. **制定固定HTML格式与命令行入口**：以统一HTML语法支撑多人协作，支持脱离平台本地编辑；平台可生成示例代码（如Flat Block），对接Web Coding任务直接投产。
4. **建立5阶段结构化研发体系**：需求梳理 → 方案设计 → 实施 → 验收（超出Testing的QA范畴） → 运营复盘（摘取内容→生成Markdown/HTML→提取数据→写成命令行工具）。
5. **设计容错协同与集体决策机制**：接受AI与人工互校的非100%准确路径；配套角色投票机制，将议题提出与事后验证结果挂钩，纳入议事云。

## 明确不做
1. 不做全自动生成：暂无法对“用户任务”及以上粒度做精准一对一生成，强依赖人工协同与试验。
2. 不做平台强绑定：优先沉淀标准、语言与规范，允许团队按语法自行操作，平台仅作为最优承载与批量处理工具。
3. 不做初始阶段的过度严谨：事件风暴允许非严谨表达先落地效果，细节严谨性留待后续迭代。

## 待确认问题
1. 原有用户故事地图的历史数据如何迁移或降级兼容？
2. “验收环节超出Testing的QA方法”具体指哪些实践、指标或工具？
3. 固定HTML格式的字段规范、版本演进与生效机制由谁主导？
4. 集体决策投票机制的角色权重、触发条件与议事云落地区域是否已明确？
5. 命令行工具与本地端侧设计环境的兼容性边界与交付形式为何？

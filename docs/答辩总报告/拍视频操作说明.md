# 产品前端操作说明（拍视频用）

> **只讲浏览器里怎么点。** 左侧点 **「使用手册」** 有白话说明 + 真实截图。  
> 完整交付说明见 [`../交付/产品操作手册.md`](../交付/产品操作手册.md)。  
> 地址：**http://127.0.0.1:8765/**

---

## 零、先选对日志（很重要）

1. 左侧点 **「日志库」** —— 可看**全部官方日志**（同步后约 60+ 条，30+ 产品流）
2. 用 **产品流 / 日期 / 用途 / 速度** 筛选
3. 点 **「选用并去工作台」** 再跑闭环

| 你想… | 选什么 | 原因 |
|------|--------|------|
| 拍视频 / 快速试跑 | **聚焦摘录**（快） | 字少，AI 更快 |
| 正式定稿、给老师看 | 对应产品流的 **按日全文** | 与官方仓库一致，可追溯 |
| 刚开完会 / 飞书片段 | **粘贴文本** 或 **上传 .md** | 不必等进库 |

原则：**先定今天要梳理的一件事 → 选产品流 → 选日期。** 不要一次糊整月。

若日志库条数很少：在仓库根目录跑一次 `python scripts\sync_journals.py` 从官方 GitHub 拉全量。

---

## 一、开拍前（2 分钟）

1. 双击仓库根目录 **`start-with-ai.bat`**
2. 浏览器会自动打开产品页；若没有，手动输入：`http://127.0.0.1:8765/`
3. **黑色窗口「AI-Server-DO-NOT-CLOSE」不要关**（关了页面就打不开）
4. 录屏：Win+G 或 OBS，建议 **1080p 全屏录浏览器**

### 界面长什么样

```
┌─────────────────────────────────────────────────────────┐
│  顶栏：产品名 ·「使用指南」· 当前日志提示                   │
├──────────┬──────────────────────────────────────────────┤
│ 工作台    │  当前日志条 + 阶段卡片                         │
│ 日志库    │  ┌──────────────┬──────────────┐            │
│ （流水线  │  │ 左：研发日志   │ 右：AI 产物   │  ← 各自滚动 │
│  只是进度）│  └──────────────┴──────────────┘            │
│          │  底部：运行 / 通过 / 打叉确认 / 定稿 / check   │
└──────────┴──────────────────────────────────────────────┘
```

**左右两栏各自有滚动条**——左边看原文、右边看产物，互不影响，不用整页滑到底。

## 二、完整操作流程（跟着点就行）

### 第 1 步：整理需求故事（Step1）

| 你做什么 | 界面上点哪里 | 等多久 |
|----------|--------------|--------|
| 让 AI 读日志、写成「一件事」 | 底部 **「▶ 运行 Step1（AI 整理故事）」** | 约 30～90 秒，会弹 loading |
| 左边对照原文 | **左栏**用鼠标滚轮或拖动滚动条 | — |
| 右边看 AI 写的需求故事 | **右栏**独立滚动 | — |
| 觉得 OK | 点 **「✓ 通过」** | 立刻 |
| 觉得不对 | 点 **「✗ 编造/分层/漏了/格式/其他」** → 填原因 → 会自动重跑 Step1 | 再等 30～90 秒 |

**通过后：** 顶部「Step1 锁定」变成 **已锁**，左侧步骤 ① 变绿。

---

### 第 2 步：提取用户故事（Step2）

| 你做什么 | 界面上点哪里 | 等多久 |
|----------|--------------|--------|
| 从故事里抽「用户要……」条目 | **「▶ 运行 Step2（AI 提取故事）」** | 约 30～90 秒 |
| 看每条故事的层级、原文出处 | **右栏**滚动，每条有彩色标签 + 引用原句 | — |
| 觉得 OK | **「✓ 通过」** | 立刻 |
| 觉得不对 | 点 **✗** + 填原因 → 只重跑 Step2 | 再等 30～90 秒 |

---

### 第 3 步：人工定稿（Step3）

| 你做什么 | 界面上点哪里 |
|----------|--------------|
| 填你的名字（或留空用默认） | 输入框 **「定稿人姓名」** |
| 生成最终文件 | **「生成定稿 accepted.json」** |
| 验收 | **「运行 check 验收」** → 右下角绿色提示 = 通过 |

**完成后：** 顶部「当前阶段」显示 **已定稿**，右栏出现 JSON 摘要。

## 三、拍视频推荐脚本（约 6～8 分钟）

| 时间 | 镜头 / 操作 | 口播示例 |
|------|-------------|----------|
| 0:00～0:30 | 全屏产品页 + 顶栏 + 左侧三步 | 「这是产品需求梳理智能体，把研发日志变成定稿需求。」 |
| 0:30～1:00 | 左栏滚动原文，指一下字数 | 「左边是完整研发日志，三千多字。」 |
| 1:00～2:30 | 点 **运行 Step1**，等 loading，右栏滚动故事 | 「AI 先整理成一件事：背景、要做什么、明确不做。」 |
| 2:30～3:00 | 点 **✓ 通过**，指「已锁」 | 「人确认通过就锁住，后面改 Step2 不会动 Step1。」 |
| 3:00～4:30 | 点 **运行 Step2**，右栏滚故事卡片 | 「再抽用户故事，每条带原文出处，禁止编造。」 |
| 4:30～5:00 | **可选**：点 ✗ 格式 + 填一句原因（演示打叉） | 「不对可以打叉，只重跑当前这一步。」 |
| 5:00～5:30 | 点 **✓ 通过** → 填定稿人 → **生成定稿** | 「最后人工定稿，留下修订记录。」 |
| 5:30～6:00 | 点 **运行 check 验收** | 「机器再验一遍，编造为零、格式合规。」 |
| 结尾 | 指四个统计卡片 + 底部 history | 「全程在 Web 里完成，人两次把关。」 |

## 四、打叉五种按钮什么意思（口播可照念）

| 按钮 | 什么时候点 |
|------|------------|
| ✗ 编造 | AI 加了原文没有的内容 |
| ✗ 分层 | 活动 / 任务 / 故事分错了 |
| ✗ 漏了 | 原文有，AI 没抓到 |
| ✗ 格式 | 不像「用户要……」这种句式 |
| ✗ 其他 | 以上都不像，但总觉得不对 |

点 ✗ 后**必须填原因**（一句话即可），系统才会重跑。

---

## 五、想从头再录一遍怎么办

页面上若显示「已定稿」：

1. 点底部 **「↺ 重新开始演示（清空产物）」**
2. 确认后，再点 **「▶ 运行 Step1」**

不用手动删文件。

---

## 六、常见问题

| 现象 | 处理 |
|------|------|
| 页面打不开 | 确认黑色 AI 窗口还在；重新双击 `start-with-ai.bat` |
| 左右不能各自滚动 | **Ctrl+F5** 强制刷新（已优化独立滚动条） |
| 点 Step1/2 一直 loading | 正常，AI 要 30～90 秒，别关黑色窗口 |
| 点 ✗ 没反应 | 先在下框填打叉原因 |
| 已是「已定稿」 | 见第五节，删 output 里几个文件再录 |

---

## 七、给老师看什么（镜头停 3 秒）

拍完后可补三个镜头（仍在浏览器 / 文件里）：

1. 右栏定稿 JSON 里的 `revisions`（有 revised / approved）
2. 资源管理器打开 `output\locked\step1-requirement-story.md`（证明锁了）
3. 点 **运行 check 验收** 出现绿色 **[OK] 全部验收门槛通过**

---

**入口汇总：** 双击 `start-with-ai.bat` → **http://127.0.0.1:8765/** → 按上面第二、三节操作即可。

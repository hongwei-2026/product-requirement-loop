# 小王怎么确认 AI 没乱写？

> 给不熟悉官方文件、第一次做人机验收的同学。发现错了，**必须写一句为什么**——不然 AI 不知道改什么，导师也没法帮你。

---

## 一、笔记到底是谁写的？

小王打开阶段 0 报告，第一反应是：「这密密麻麻的，是 AI 编的，还是人写的？」

导师说：**两样都有。**

AI 先根据官方仓库和日志，把阅读笔记、故事草稿写出来——因为没人愿意从零啃十几份 GitHub 文档。  
但 AI 写完不算数。**小王要用自己的眼睛验收**：关键词对得上吗？来源原句在不在？  
最后他在 [阶段0快速验收清单](./阶段0快速验收清单.md) 上打勾签字，才算「我读过了，敢开工」。

所以不是「AI 说了算」，也不是「小王从零写笔记」。是 **AI 起草，人拍板**。

---

## 二、文件不熟，怎么找得到？

小王坦白：「你让我打开某个 yaml，我连在哪都不知道。」

解决办法很简单：**别通读全文。**

他打开 `project/trials/case-01/review.html`，点顶上的「捕捉用户故事」。左边原文里，这句话立刻被标黄。  
再看右边：有没有一条故事，意思对得上？

更完整的词表在 [复核关键词卡-case01.md](./复核关键词卡-case01.md)。每个词都是日志里真实出现的，Ctrl+F 一般都能搜到。  
**搜得到 → 右边应该有；搜不到但右边出现了 → 多半有问题。**

## 三、发现问题要打叉——但必须写一句为什么

有一天，小王在右边看到一条：「用户要对接飞书 API」。  
他在左边搜了半天，根本没有「飞书」两个字。

他点 ✗ **编造**，然后在下面写了一句：

> 右边写了飞书，原文没提。

系统收到的是：

```text
revise:编造:右边写了飞书，原文没提
```

**这不是形式主义。** 真实项目里，如果只打叉不写原因，跑 Loop 的人只能猜——猜错了，你又得重来一轮。  
所以原因不能省——但**不要求你会写**，只要求有一句能看懂的话。

---

## 三点五、只会说「不对」，不会写原因怎么办？

小王盯着右边看了半天：「我知道这条有问题，但让我描述……说不清。」

导师说：**你不用从零写。** 照下面三步走，往往填一个词就够：

```
1. 先判断大概哪类问题 → 点 ✗ 编造 / 分层错 / 漏了 …
2. 点 review.html 里现成的一句（几乎不用改）
3. 若句式里有个空 → 只填一个词，点「拼成一句」
```

举例：

| 小王的情况 | 他点的 | 他填的一个词 | 最后生成的原因 |
|------------|--------|--------------|----------------|
| 右边多了「飞书」，左边没有 | ✗ 编造 | 飞书 | 右边写了「飞书」，原文没有 |
| 左边有「人去调整」，右边没有 | ✗ 漏了 | 人去调整 | 左边「人去调整」右边没有对应条目 |
| 分不清活动还是任务 | ✗ 分层错 | （不用填）点现成句 | 这条应该是任务，不是故事 |
| 就是别扭，说不清 | ✗ 其他 | （不用填）点现成句 | 右边和左边对不上，我说不清属于哪一类 |

**关键：** 系统要的不是作文，是**让下一个人知道往哪改**。  
你点现成句式、或填一个词拼出来的那句话，就算合格原因。

`review.html` 里不填原因，**生成不了** revise 指令——但你可以**点一句现成的**，不用自己憋。

写一句就行，不用长篇大论。若不用页面，手写也按同样句式：

| 你觉得 | 点哪个 | 照着填（把 XXX 换成你看到的词） |
|--------|--------|--------------------------------|
| 右边多了原文没有的东西 | ✗ 编造 | 右边写了 XXX，原文没有 |
| 活动/任务/故事分错了 | ✗ 分层错 | 这条应该是任务，不是故事 |
| 左边重要句右边没有 | ✗ 漏了 | 左边「XXX」右边没有对应条目 |
| 没用「用户要」开头 | ✗ 格式 | 这条没用用户要开头 |
| 以上都不贴切 | ✗ 其他 | 右边和左边对不上，我说不清属于哪一类 |

系统会把你的原因记进 `revisions`，例如：

```json
{
  "round": 2,
  "action": "revised",
  "code": "编造",
  "comment": "右边写了飞书，原文没提",
  "at": "2026-08-30T18:00:00+08:00"
}
```

## 四、重跑：别让我把已经对过的再确认一遍

小王又担心：「我 Step1 都通过了，Step2 有一条错了，难道要从头跑？万一以前对的又被改坏？」

设计是这样想的：

1. **你点 ✓ 通过的** → 锁定。默认不再问你。  
2. **你点 ✗ 的** → 只重跑**当前这一步**，带着你写的那句原因。  
3. **已经锁定的故事** → AI 不能覆盖；只重生成没通过的那些。  
4. **你想改以前通过的** → 点「解锁」，才会重新问你。

对应命令（阶段 4 跑 Loop 时用）：

```text
ok                                    # 通过并锁定
revise:编造:右边写了飞书，原文没提      # 只重跑当前步，原因跟在后面
unlock:step1                          # 你想改已通过的 Step1 才用
```

所以：**你确认过的，不会因为别处错了就让你全部重来。**

## 五、图在 VS Code 里看不见？

小王打开 `阶段0实现报告.md`，图全是裂的。

最常见的原因：`screenshots/` 里还没有 PNG。可以进 `screenshots` 目录跑 `node capture_all.mjs` 重新截图。

看图最稳的方式：**用浏览器打开 [图文预览.html](./图文预览.html)**。  
VS Code 里也可以：打开 md 文件后按 `Ctrl+Shift+V` 开预览（不是只看编辑窗格）。

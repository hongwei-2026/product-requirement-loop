# 阶段 0 自测工作流说明

> **给谁看：** 你想知道「AI 说 26 项全过，到底测了啥、为啥那么快、人的体验算不算」  
> **一句话：** 自动自测分两层——**机器层**（快，查文件和代码）+ **体验层**（慢几秒，真用浏览器点页面）。**你亲手验收**是第三层，三层都不能互相代替。

---

## 开篇：为啥一秒就「全过了」？

小王跑完 `python scripts/verify_stage0.py`，看见：

```
合计: 26 项, 通过 26, 失败 0
```

他嘀咕：「我验收手册要写半小时，你怎么一秒就完了？」

老实说：**那一秒测的不是你有没有读懂资料，也不是你点按钮顺不顺手。**  
它测的是——交付物有没有齐、关键文件里有没有该出现的字、yaml 能不能解析、截图文件在不在。

就像装修完工前，监理先核对：**图纸在不在、材料单齐不齐、门牌号对不对**——还没进去试坐沙发舒不舒服。

所以要分三层看：

| 层 | 谁跑 | 测什么 | 快不快 |
|----|------|--------|--------|
| **机器层** | `verify_stage0.py` | 文件、字段、字符串 | 约 1 秒 |
| **体验层** | `verify_stage0_ux.mjs` | 浏览器真点 review.html | 约 10～20 秒 |
| **人工层** | 你 + [阶段0验收操作手册](./阶段0验收操作手册.md) | 读资料、对官方链接、签字 | 30～40 分钟 |

**26 项全过 ≠ 阶段 0 对你个人验收完成。**  
只说明：**我交付的包裹没缺件。**

## 第一层：机器层自测（`verify_stage0.py`）

### 怎么跑

```powershell
cd 课题申请-product-requirement-loop
python scripts/verify_stage0.py
python scripts/verify_stage0.py --write-report stage0-self-test-report.md
```

### 它实际上在干什么？

每条检查都是 **读磁盘上的文件**，不做这些事：

- ❌ 不打开浏览器  
- ❌ 不访问 GitHub  
- ❌ 不读你 Fork 的仓库  
- ❌ 不判断你读没读懂报告  
- ❌ 不验证截图内容是否和官方网页一致（只验证 PNG 文件存在）

### 26 项逐项说明

#### D01～D08：文档在不在

| ID | 测法 | 确定什么 | **没测什么** |
|----|------|----------|--------------|
| D01～D08 | `Path.exists()` | 阶段 0 该交的 md/html 有没有 | 写得对不对、你能不能看懂 |

#### I01～I03：输入可追溯

| ID | 测法 | 确定什么 | **没测什么** |
|----|------|----------|--------------|
| I01 | 文件存在 | 有 `journal-raw.md` | 摘录是否和官方**全文**一致 |
| I02 | 字符串包含 | 含「捕捉用户故事」「零碎话语」 | 是否漏了别的关键句 |
| I03 | SOURCE.md 含仓库名 | 留了来源说明 | 链接能不能打开 |

#### U01～U04：验收页「代码层面」

| ID | 测法 | 确定什么 | **没测什么** |
|----|------|----------|--------------|
| U01 | review.html 存在 | 有对照页文件 | 浏览器里左边会不会空白 |
| U02 | html 含 `data-kw="捕捉用户故事"` | 做了关键词按钮 | 点了会不会真的高亮 |
| U03 | html 含 `TEMPLATES` 和 `buildRevise` | 做了句式模板逻辑 | 空原因时会不会拦住 |
| U04 | html 含「锁定」「unlock」 | 文案写了重跑规则 | 阶段 4 锁定是否真的生效 |

#### L01～L05：Loop 骨架

| ID | 测法 | 确定什么 | **没测什么** |
|----|------|----------|--------------|
| L01 | yaml 存在 | 有 Loop 定义文件 | 内容是否合理 |
| L02 | `yaml.safe_load` + 键集合 | 有 entry/exit/steps 等 | 和官方 devops-code 逐字对齐 |
| L03 | `fabrication_count == 0` | 声明了数值门槛 | 真实跑出来的数据 |
| L04～L05 | 文件存在 | check.py、schema 在 | 脚本跑起来是否全绿 |

#### S01、S02：截图文件

| ID | 测法 | 确定什么 | **没测什么** |
|----|------|----------|--------------|
| S01 | 数 PNG ≥ 7 | 有图可贴文档 | 图是不是糊的、截错页面 |
| S02 | 3 张必附图存在 | 课题关键图在 | VS Code 里能不能显示 |

#### M01～M02：验收手册

| ID | 测法 | 确定什么 | **没测什么** |
|----|------|----------|--------------|
| M01 | 手册文件存在 | 给你逐步操作文档 | 你跟着做是否顺畅 |
| M02 | 正则搜 `screenshots/stage0/` | 手册里引了操作截图 | 截图和文字是否对得上 |

## 第二层：体验层自测（`verify_stage0_ux.mjs`）

### 为啥要有这层？

因为人的体验问题，**光看 html 源码发现不了**。例如：

- `fetch('input/journal-raw.md')` 写对了，但用错方式打开页面 → 左边仍可能空白  
- `buildRevise` 函数在，但空原因时若还能生成指令 → 违背「必须写原因」

这一层用 **Playwright 无头浏览器**，模拟真人点几下。

### 怎么跑

```powershell
cd 课题申请-product-requirement-loop
node scripts/verify_stage0_ux.mjs
```

会生成 [stage0-ux-self-test-report.md](./stage0-ux-self-test-report.md)。

### 8 项体验检查

| ID | 模拟人的动作 | 期望 | 对应功能 |
|----|--------------|------|----------|
| UX01 | 打开 review.html | 左边出现日志正文，不是「加载中」 | 左右对照能开工 |
| UX02 | 点「捕捉用户故事」 | 原文出现黄色高亮 | 关键词卡落地 |
| UX03 | 点「✓ 通过」 | 底部指令变成 `ok` | 锁定本步 |
| UX04 | 点「✗ 编造」 | 出现句式模板区域 | 不会写原因有引导 |
| UX05 | 不填原因点「生成」 | 不生成 revise / 有提示 | 打叉必须留痕 |
| UX06 | 点一句现成句式 | 原因框自动填入 | 降低描述门槛 |
| UX07 | 再点「生成」 | 出现 `revise:编造:…` | Loop 可读的反馈 |
| UX08 | 看右边 | 至少 3 条示例故事 | 布局可读 |

### 体验层仍然没测什么？

- ❌ 你在 **VS Code 预览** 里看图（只测了 review 页）  
- ❌ 手机窄屏排版  
- ❌ 你读 [阶段0实现报告](./阶段0实现报告.md) 是否理解  
- ❌ 你和 Fork 仓库里官方原文逐句核对（那是你的验收手册第三章）

## 诚实总结：我考虑人的体验了吗？

| 方面 | 做了啥 | 还不够啥 |
|------|--------|----------|
| 不熟文件 | 关键词卡 + review 高亮 + 体验层 UX02 | 要你亲自点一次确认顺手 |
| 不会写原因 | 句式模板 + UX05～UX07 | 极端情况还要不要更多例句，得你反馈 |
| 怕重跑折腾 | 文档写锁定规则 | 阶段 4 代码还没实现锁定 |
| 看图难 | 图文预览.html + 截图 | VS Code 预览因环境而异 |
| 验收太累 | 快速清单 10 条 + 详细手册分章 | 不能替你做「读懂资料」 |

**设计原则：** 机器查「有没有」，浏览器查「点不点得动」，你查「懂不懂、敢不敢签字」。

### 真实案例：体验层曾抓到一个机器层抓不到的 bug

第一版 `review.html` 用 `fetch('input/journal-raw.md')` 读左边原文。  
机器层 U01 只检查 **html 文件存在** → PASS。  
体验层 UX01 用浏览器 **双击打开**（`file://` 协议）→ **左边空白** → FAIL。

原因：浏览器安全策略禁止 `file://` 页面去 fetch 本地别的文件。  
修复：在 html 里内嵌一份 `journal-raw` 副本作兜底；改日志后跑 `python scripts/sync_journal_embed.py` 同步。

这说明：**为啥要快跑体验层**——有些问题只有「像人一样打开页面」才会暴露。

### 真实案例 2：双击 bat 闪退（启动层）

第一版 `start_stage0.ps1` 在脚本里直接写中文路径 + `ReadKey`，在 Windows PowerShell 下 **解析失败**，双击 bat 窗口一闪就关。

机器层当时 **没有测 ps1 语法**，所以报告仍显示 26 项全过。

修复：

- 重写 ps1（ASCII 为主）  
- 中文路径改放 `launcher-files.json`（UTF-8）  
- bat 末尾加 `pause`，失败也能看见报错  
- 新增 `打开验收页.bat` 兜底  
- 机器层新增 P01～P06 检查启动器

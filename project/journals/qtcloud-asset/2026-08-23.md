像资产云的话，我们其实已经大概知道它要长什么样子了。基本上来讲：
1. 前台（客户端层）：实际上就是网盘。
2. 高级功能：主要体现在对资产格式规则的维护，包括各种命名规则、语义上的维护等。
3. 规则实现：有很多理论上可以硬编码的规则。

我觉得这也是可以演化式的：
首先告诉他，要把所有的 GitHub 和我们的对象存储维护起来。
然后，从这里面找规律，看怎么才能更好地维护。通过人机交互找到一个合适的结构，找着找着，就能找到一个资产运营的 MVP 了。

我们都不需要提前去设计它的结构，只需要告诉它明确的方向、我要的目的以及大概预想的效果，然后让它摸索和演化就可以。其实可以给它很多自主的空间去发挥。

我们现在的系统里面，主要缺少一种在极其有限的上下文中，将其变得足够精密的技术。虽然现在已经越变越精密了，但这种精密程度相比于软件和业务所需要的精密与准确程度，其实还不是太够。
